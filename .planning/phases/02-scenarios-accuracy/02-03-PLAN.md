<objective>
Calibrate token budgets for all 16 benchmark tasks and tune the admission control threshold based on profiled file sizes from heavyweight scenarios.

Purpose: Without calibrated budgets, ctx-rm mode either never evicts (budget too high) or starves the agent (too low). Each task needs a budget set to 40-60% of its total injected context to guarantee 3+ eviction cycles. The admission threshold (currently hardcoded at 2000 tokens) should be tuned based on actual file read sizes so large files go to Warm while small reads stay Active.

Output: budget_map.py with per-task calibrated budgets and tuned admission threshold, runner integration, tests.
</objective>

**Step 1: Profile all tasks.**
Write a script (or inline code) that loads every task from the YAML and computes total injected tokens:
```python
total_tokens = sum(needle.content token estimate for needle in task.needles)
             + sum(injection.size_tokens for injection in task.context_injections)
             + estimate_tokens(system_prompt)  # ~200 tokens
             + estimate_tokens(task_instruction)  # ~100 tokens
```

Use `ctx_rm.core.tokenizer.estimate_tokens` for the text-based estimates (chars/4) and the YAML's `size_tokens` field directly for noise injections.

**Step 2: Create `src/ctx_rm/benchmarks/budget_map.py`.**
Contents:
```python
"""Calibrated token budgets for benchmark tasks.

Each budget is set to ~50% of the task's total injected context
(needles + noise + system + task instruction) to guarantee
3+ eviction cycles during ctx-rm mode runs.

Admission threshold tuned from profiled SCALE fixture file sizes:
- Small files (< 100 lines, ~400 tokens): stay Active
- Medium files (100-300 lines, ~1200 tokens): stay Active
- Large files (300+ lines, ~2000+ tokens): bypass to Warm
Threshold set at 1500 tokens (75th percentile of fixture file sizes).
"""

# task_id -> calibrated token budget (ctx-rm mode)
BUDGET_MAP: dict[str, int] = {
    # Original tasks (CR-001 through CR-010, MULTI-001, TRACE-001, SPEC-001)
    # Computed as ~50% of (needle_tokens + noise_tokens + overhead)
    "CR-001": 1800,   # total ~3500: 2500 noise + ~200 needles + ~300 overhead
    "CR-002": 1400,   # total ~2800: 1800 noise + ~200 needles + ~300 overhead
    "CR-003": 2500,   # total ~5000: 4000 noise + ~200 needles + ~300 overhead
    "CR-004": 4500,   # total ~9000: 8000 noise + ~200 needles + ~300 overhead
    "CR-005": 3500,   # total ~7000: 6000 noise + ~200 needles + ~300 overhead
    "CR-006": 4000,   # total ~8000: 7000 noise + ~200 needles + ~300 overhead
    "CR-007": 1800,   # total ~3500: 2500 noise + ~200 needles + ~300 overhead
    "CR-008": 1500,   # total ~3000: 2000 noise + ~200 needles + ~300 overhead
    "CR-009": 2000,   # total ~4000: 3000 noise + ~200 needles + ~300 overhead
    "CR-010": 3000,   # total ~6000: 5000 noise + ~200 needles + ~300 overhead
    "MULTI-001": 1500, # total ~3000: 2000 noise + ~200 needles + ~300 overhead
    "TRACE-001": 2000, # total ~4000: 3000 noise + ~200 needles + ~300 overhead
    "SPEC-001": 1500,  # total ~3000: 2000 noise + ~200 needles + ~300 overhead
    # SCALE tasks (heavyweight -- high eviction pressure)
    "SCALE-001": 10000,  # total ~20K: 17K noise + 1K needles + ~2K overhead
    "SCALE-002": 15000,  # total ~30K: 25K noise + 1K needles + ~4K overhead
    "SCALE-003": 20000,  # total ~40K: 35K noise + 2K needles + ~3K overhead
}

# Admission control threshold (tokens).
# File reads above this size bypass Active and go directly to Warm.
# Tuned from SCALE fixture file sizes:
#   p25=~300tok, p50=~800tok, p75=~1500tok, p90=~2500tok
# Set to p75 to keep most reads in Active while routing large dumps to Warm.
ADMISSION_THRESHOLD: int = 1500
```

Compute the ACTUAL values by running the profiling script against the YAML. The values above are estimates -- replace with computed values. Each budget should be between 40% and 60% of the total.
