<task type="auto">
  <name>Task 2: Build results analyzer module with evidence computation</name>

  <action>
    Create `src/ctx_rm/benchmarks/analyzer.py` with three analysis functions that read experiment output directories and compute evidence metrics.

    **Function 1: `compute_eviction_accuracy(results_dir: Path) -> list[EvictionAccuracyRow]`**

    For EVID-01. Reads metrics.json from each run directory under results_dir. For each (task_id, policy) group:
    - Count eviction events where source starts with "noise:" → noise_evictions
    - Count eviction events where source starts with "needle:" → needle_evictions
    - Count other evictions (tool results, user messages, etc.)
    - Compute noise_ratio = noise_evictions / (noise_evictions + needle_evictions) if both exist
    - Return as dataclass with: task_id, policy, noise_evictions, needle_evictions, other_evictions, noise_ratio, total_evictions

    The function walks the results directory tree. The BenchmarkRunner creates: `{output_dir}/{task_id}/ctx-rm/{driver}/{policy}/run-{N}/metrics.json`. Parse the directory structure to extract task_id and policy.

    **Function 2: `compute_recall_comparison(recall_on_dir: Path, recall_off_dir: Path) -> list[RecallComparisonRow]`**

    For EVID-02. Reads evaluation.json from both experiment directories. For each task_id:
    - From recall_on_dir: collect pass rates and median tokens across runs
    - From recall_off_dir: collect pass rates and median tokens across runs
    - Return as dataclass: task_id, pass_rate_on, pass_rate_off, median_tokens_on, median_tokens_off, recall_count_median

    **Function 3: `compute_budget_knee(results_dir: Path) -> list[BudgetKneeRow]`**

    For EVID-03. Reads evaluation.json from budget sweep results. For each budget level:
    - Collect pass rate across runs
    - Collect median prompt tokens across runs
    - Return as dataclass: task_id, budget, pass_rate, median_prompt_tokens, median_eviction_count

    Also include the full-mode baseline row (budget=1000000, pass_rate, tokens).

    The "knee" itself is identified by finding the lowest budget where pass_rate equals the full-mode pass_rate. Return this as a separate `KneePoint` dataclass: task_id, knee_budget, full_mode_tokens, knee_tokens, token_savings_pct.

    **Function 4: `find_knee_point(rows: list[BudgetKneeRow], full_mode_rate: float) -> KneePoint | None`**

    Helper that scans budget rows in ascending budget order and returns the first budget where pass_rate >= full_mode_rate.

    **All dataclasses**: Use `@dataclass` for all return types (EvictionAccuracyRow, RecallComparisonRow, BudgetKneeRow, KneePoint).

    **Tests** (`tests/benchmarks/test_analyzer.py`):
    Create tests using synthetic metrics.json and evaluation.json files in tmp_path:

    1. `test_eviction_accuracy_counts_noise_vs_needle` — Write a metrics.json with evictions having source="noise:foo" and source="needle:bar", verify noise_ratio computation.
    2. `test_eviction_accuracy_handles_no_evictions` — Empty evictions list returns 0/0 gracefully.
    3. `test_recall_comparison_pass_rates` — Two result dirs with different pass rates, verify comparison.
    4. `test_budget_knee_finds_lowest_matching` — Budget rows with varying pass rates, verify knee detection.
    5. `test_budget_knee_returns_none_when_no_match` — All pass rates below full mode, returns None.

    Directory structure for test fixtures: mirror the BenchmarkRunner output structure:
    `{tmp_path}/{task_id}/ctx-rm/llamacpp/{policy}/run-1/metrics.json`
    `{tmp_path}/{task_id}/ctx-rm/llamacpp/{policy}/run-1/evaluation.json`
    `{tmp_path}/{task_id}/full/llamacpp/run-1/evaluation.json`
