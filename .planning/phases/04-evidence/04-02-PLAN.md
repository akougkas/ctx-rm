  <action>
    **Part A: Create EVID-05 context window scaling config** (`docs/experiments/context_window_scaling.yaml`)

    Tests ctx-rm quality at different effective context window sizes. Uses budget as a proxy for window size (since the model's physical context window is fixed, but ctx-rm enforces an effective budget).
    ```yaml
    name: context-window-scaling
    output_dir: ./results/experiments/context-window-scaling
    runs: 3
    max_turns: 30
    tasks: [SCALE-001, SCALE-002, SCALE-003]
    modes: [ctx-rm, full]
    policies: [budget]
    budgets: [4000, 8000, 16000, 32000]
    scorer: heuristic
    enable_recall: true
    ```
    Purpose: At each window size (4K/8K/16K/32K), does ctx-rm maintain task quality? Full mode provides the unbounded baseline. With 3 SCALE tasks at 17K-35K total injection, these budgets exercise different regimes: 4K is severely constrained, 32K is generous.

    **Part B: Create EVID-04 noise degradation config** (`docs/experiments/noise_degradation.yaml`)

    Tests whether full context (retaining all noise) causes model degradation while ctx-rm (evicting noise) succeeds.
    ```yaml
    name: noise-degradation
    output_dir: ./results/experiments/noise-degradation
    runs: 5
    max_turns: 30
    tasks: [SCALE-001, SCALE-002, SCALE-003, CR-004, CR-006, CR-010, SPEC-001]
    modes: [ctx-rm, full]
    policies: [budget]
    budgets: []
    scorer: heuristic
    enable_recall: true
    ```
    Purpose: Run the noisiest tasks (SCALE tasks have 17K-35K noise, CR-004/006/010 have 5K-8K noise, SPEC-001 is the original proof). 5 runs for statistical confidence. The hypothesis: on at least one task, full mode pass rate < ctx-rm pass rate because noise degrades the small model.

    **Part C: Extend analyzer.py with two new functions**

    Add to `src/ctx_rm/benchmarks/analyzer.py`:

    **`compute_scaling_quality(results_dir: Path) -> list[ScalingRow]`**

    For EVID-05. Reads evaluation.json from scaling experiment output. For each (task_id, budget):
    - Collect pass rate and median prompt tokens from ctx-rm runs
    - Also extract full-mode baseline (budget=1000000 or mode=full)
    - Return as dataclass: task_id, budget, pass_rate, median_prompt_tokens, full_mode_pass_rate

    **`find_noise_degradation(results_dir: Path) -> list[NoiseDegradationRow]`**

    For EVID-04. Reads evaluation.json from noise degradation experiment. For each task_id:
    - ctx_rm_pass_rate: pass rate across ctx-rm runs
    - full_pass_rate: pass rate across full runs
    - delta: ctx_rm_pass_rate - full_pass_rate (positive means ctx-rm is better)
    - is_degradation_candidate: True if delta > 0 (ctx-rm better than full)
    - Return as dataclass: task_id, ctx_rm_pass_rate, full_pass_rate, delta, is_degradation_candidate, num_runs

    **Part D: Add tests**

    Add to `tests/benchmarks/test_analyzer.py`:
    1. `test_scaling_quality_extracts_per_budget_rates` — Synthetic data at 3 budget levels, verify pass rates extracted.
    2. `test_noise_degradation_identifies_candidate` — Synthetic data where ctx-rm passes 80% and full passes 40%, verify is_degradation_candidate=True.
    3. `test_noise_degradation_no_candidate` — Synthetic data where full passes higher, verify is_degradation_candidate=False.

  <action>
    Add a new `analyze` command to the CLI that reads experiment output directories and prints Rich tables summarizing evidence.

    **Command signature:**
    ```python
    @app.command()
    def analyze(
        results_dir: Path = typer.Argument(..., help="Experiment results directory"),
        analysis: str = typer.Option("all", help="Analysis type: eviction, recall, budget, scaling, noise, all"),
    ) -> None:
    ```

    **Implementation:**

    1. Import analyzer functions from ctx_rm.benchmarks.analyzer.
    2. Based on `analysis` parameter, call the appropriate function(s).
    3. For each analysis type, build a Rich Table with color-coded columns:

    **eviction** — Table: Task | Policy | Noise Evictions | Needle Evictions | Noise Ratio
    - Color: noise_ratio >= 0.8 → green (good: mostly noise evicted), < 0.5 → red (bad: needles evicted early)

    **recall** — Table: Task | Recall On Pass% | Recall Off Pass% | Delta | Recall Count
    - Color: delta > 0 → green (recall helps), delta < 0 → red (recall hurts)

    **budget** — Table: Task | Budget | Pass Rate | Med Tokens | Evictions
    - Highlight the knee row in bold green
    - Add a summary line: "Knee at {budget} tokens = {savings}% fewer tokens than full mode"

    **scaling** — Table: Task | Budget | Pass Rate | Med Tokens | Full Mode Rate
    - Color: pass_rate == full_mode_pass_rate → green, otherwise yellow

    **noise** — Table: Task | ctx-rm Pass% | Full Pass% | Delta | Candidate?
    - Color: is_degradation_candidate → bold green "YES", otherwise dim "no"

    **all** — Run all five analyses sequentially, with Panel headers separating each section.

    If a results directory doesn't contain the expected structure (e.g., no eviction data), print a dim message: "No {analysis} data found in {results_dir}" and skip gracefully.
  </action>
