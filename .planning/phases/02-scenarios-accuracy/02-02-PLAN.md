<objective>
Make scoring source-aware with configurable weights and enhance recall to be content-triggered, budget-bounded, and precision-tracked.

Purpose: The scorer needs per-source weights so BudgetAwarePolicy knows needles are precious (0.9) and noise is expendable (0.1). Recall currently only uses the task text as query; content-based recall catches the critical case where an agent re-reads a file it previously read but that was evicted. Recall budget prevents context explosion. Precision tracking measures recall effectiveness.

Output: Updated scorer with configurable weights, loop with content-based recall + budget + precision tracking, comprehensive tests.
</objective>

No breaking changes.

**loop.py -- RECALL-01 (content-based recall):**
Add a `_try_content_recall()` method that runs AFTER each tool result is ingested (inside the tool call processing loop). Logic:
1. After ingesting a tool result, check if the tool was `file_read` and extract the file path from the tool arguments
2. Search evicted segments using `bus.search_evicted(file_path, top_k=self.recall_top_k)` where file_path is the path argument from the file_read call
3. Apply the same source filter (`_RECALLABLE_SOURCES`) and `_recalled_ids` dedup as existing `_try_recall`
4. Recall matching segments via `bus.recall(seg.seg_id)`
5. Increment `_recalls_made` and add to `_recalled_ids`

Also search by content snippet: if the tool result contains a filename or path that matches an evicted segment's source, trigger recall.

**loop.py -- RECALL-02 (recall budget):**
Add `recall_budget: int = 3` parameter to AgentLoop.__init__. Track `_recalls_this_turn: int = 0`. Reset to 0 in each turn (at the start of the turn loop, where `bus.advance_turn()` is called). In both `_try_recall` and `_try_content_recall`, check `_recalls_this_turn < self.recall_budget` before recalling. Increment after each successful recall.

**loop.py -- RECALL-03 (recall precision tracking):**
Add tracking state:
- `_recall_precision_total: int = 0` (total recalls)
- `_recall_precision_hits: int = 0` (recalls whose content appeared in subsequent tool calls)
- `_recalled_contents: dict[str, str] = {}` (maps seg_id -> content snippet for checking)

After each recall, store the recalled segment's content (first 200 chars) in `_recalled_contents` and increment `_recall_precision_total`.

After each tool result is ingested, check if any recalled content snippet appears in the result text. If yes, increment `_recall_precision_hits` and remove from tracking dict (one-shot).

Add `recall_precision` to AgentResult: `recall_precision_hits / recall_precision_total` (0.0 if total is 0).

Update `_build_result` to include the new field.

Do NOT change `_try_recall` signature or the existing recall search-by-task-text logic -- only ADD the content-based recall alongside it.
